# V3-C: the code editor and Java execution

Written 2026-11-19. Branch `worktree-agent-a4d7fa36120b809a2`. Measurements were taken on the lead's
desktop (Windows 11, Node 24.3, headless Chromium from Playwright 1.62) unless a line says otherwise.

## Short answer

- **Java runs in the browser now, self-hosted, free:** TeaVM's `javac` compiled to WebAssembly,
  built from source by us, served from `/teavm/` on our own domain. Students get `Scanner` on stdin,
  `BufferedReader`, `printf`, collections, streams, records, switch patterns, and javac's own
  compile errors with line and column, marked in the editor.
- **Recommendation:** ship option A (TeaVM, in the browser) for practice, lessons and duels. Keep
  option B (a JDK in Cloudflare Containers) written up as the upgrade for when a judged result must
  be trusted (contests with points) or when the TeaVM gaps below start to bite. B needs the Workers
  Paid plan ($5 a month) and Docker on whoever deploys. That is the lead's call.
- **CheerpJ (C):** still not free to self-host. Free use must load from `cjrtnc.leaningtech.com`.

## Part 1: the editor

`src/components/Editor.jsx` on CodeMirror 6. CodeMirror lives in `src/lib/cm.js`, loaded with a
dynamic import on first use (`cm-*.js`, 499 KB raw, 172 KB gzip). Pages without an editor load
none of it. If the chunk cannot load, a plain text box takes its place.

- Line numbers, fold markers, active line, Java and Python highlighting with colours from CSS
  variables (`--code-*` in the V3-C block of `src/index.css`), JetBrains Mono at 14px (15px from
  900px wide).
- Bracket matching and auto-close, indent on Enter, 4-space indent unit.
- Tab indents, Shift+Tab outdents. Esc then Tab moves focus on (CodeMirror's tab focus mode;
  checked in Chromium: focus lands on the next control).
- Completion: Java keywords and common classes, snippets (`sout`, `main`, `fori`, `scanner`), and
  every word already in the file. Python gets CodeMirror's local and builtin completion plus file words.
- Ctrl+Enter (Cmd+Enter on a Mac) runs.
- `diagnostics` prop: `[{ line, col?, message, severity? }]` becomes a red squiggle, a gutter dot
  and a hover tooltip. An error past the end of a line (javac's `';' expected`) marks the last token.
- Fix outside V3-C's files: the site's "/" command-bar shortcut stole focus from any
  contenteditable element, so "/" could not be typed in the editor. `Chrome.jsx` now skips
  contenteditable targets (one condition).

Try it: `/lab/editor` in a dev build, or `/lab/editor?editor=1` anywhere. Problem pages and the
workspace still use the old textarea; moving them is wave 7.

## The run interface

`src/lib/run/index.js`, as v2-spec section 6:

```
run({ lang, source, stdin, timeoutMs, onPhase })
  -> { stdout, stderr, exitCode, timeMs, timedOut, diagnostics, compileError? }
judge({ lang, source, cases, timeoutMs, onPhase })
  -> { passed, results: [{ ok, stdout, stderr, expected, exitCode, timeMs, timedOut }], diagnostics, compileError? }
```

`onPhase` hears `loading` (first run only), `compiling`, `running`, so the page can say what it is
waiting for. Python wraps `src/lib/pyrunner.js` (a SyntaxError counts as `compileError`, and the
traceback's last line in the student's file becomes a diagnostic). Java compiles once per `judge`
and runs each case in a fresh instance. Each run has its own time limit; compile time does not count.

## Part 2: Java options, with evidence

### A. TeaVM javac in the browser (chosen)

What it is: OpenJDK's javac and the TeaVM compiler, both compiled to one WebAssembly module
(https://github.com/konsoletyper/teavm-javac). javac turns the student's source into class files;
TeaVM turns those into a small WebAssembly program, which we run in a worker.

**The published build does not work for us.** I first tested the files on teavm.org's playground
(`/playground/3/`). Its compile class library was generated by an older converter that ignored
TeaVM's `@Rename`, so javac could not see `Throwable.getMessage()`, `Object.getClass()`,
`Throwable.getStackTrace()` (they appear as `getMessage0` etc.), and `StringBuilder.append(Object)`
was ambiguous. `printf("%.2f")`, `DecimalFormat` and array `clone()` crashed with a null pointer,
`InputStreamReader` failed to build, and exceptions were uncatchable traps.

**Building from source fixed nearly all of it.** teavm-javac at commit `0340fab` needs Java 25
(the README's "Java 21" is out of date) and a published TeaVM. I changed one line in my scratch copy
(`gradle/libs.versions.toml`: `teavm = "0.17.0-dev-7"`, since `0.17.0-SNAPSHOT` is not published)
and ran `./gradlew :compiler:createDist`. 6 min 13 s, nothing else installed (the wrapper fetches
Gradle 9.1, the build fetches the jdk25u source). The stack deobfuscator comes from the
`org.teavm:teavm-wasm-gc-deobfuscator:0.17.0-dev-7` jar. The result is committed in `public/teavm/`
with a `NOTICE.txt` (Apache 2.0, OpenJDK GPLv2 with Classpath Exception).

Files (all under the 25 MiB Workers asset limit):

| file | raw | gzip |
|---|---|---|
| compiler.wasm | 4.86 MB | 1.85 MB |
| runtime-classlib-teavm.bin (already gzip) | 2.44 MB | 2.40 MB |
| compile-classlib-teavm.bin (already gzip) | 0.21 MB | 0.21 MB |
| deobfuscator.wasm | 49 KB | 22 KB |
| compiler.wasm-runtime.js | 18 KB | 6 KB |
| **total** | **7.58 MB** | **about 4.5 MB** |

Downloaded once on the first Java run (or when a page calls `warmUp('java')`), then from the
browser cache. Same origin, so the school filter sees only peshcompsci.org.

**stdin and Scanner.** TeaVM has no `java.util.Scanner`, its `System.in` always hits end of file,
and its `InputStreamReader` will not build for WebAssembly. Instead of patching TeaVM, the runner
rewrites the source before javac sees it (`src/lib/run/javaSource.js`):

- blanks `import java.util.Scanner;` and `import java.io.InputStreamReader;` with spaces,
- turns `System.in` into `$Stdin.in` and `System.exit` into `$Stdin.exit` (same length; both
  `System` and `$Stdin` are 6 characters), skipping strings and comments,
- appends small `Scanner`, `InputStreamReader` and `InputMismatchException` classes after the
  student's last line. A top-level class in the file shadows `java.util.*`, so their code compiles
  unchanged.

Every edit keeps each line's length, so javac's line and column point at the student's own text
with no mapping. A generated `$Run` class feeds stdin, calls the student's `main`, and prints an
uncaught exception the way Java does, keeping only frames on the student's lines.

**What was checked** (Node, the real engine; also `test/java-engine.test.js`, which runs in `npm test`):
Scanner (`nextInt`, `nextLong`, `nextDouble`, `nextLine` after `nextInt`, `hasNext*`), UTF-8
input, BufferedReader + StringTokenizer + PrintWriter(BufferedWriter(OutputStreamWriter(System.out))),
`printf`/`String.format` with `%d %s %.2f %5.1f %x %-3s %b`, DecimalFormat, HashMap/TreeMap/TreeSet/
PriorityQueue with a lambda comparator/ArrayDeque/LinkedList/iterators, `Arrays.sort` with a
comparator, `Arrays.deepToString`, streams and Collectors, BigInteger, BigDecimal, records, sealed
interfaces with switch patterns, text blocks, `var`, `instanceof` patterns, inner and nested classes,
generics, user exceptions, catching ArrayIndexOutOfBounds/NullPointer/ClassCast/NumberFormat,
`System.exit`, a public class named `Solution`, a missing `main`.

**Known gaps (A)**

- `array.clone()` crashes inside TeaVM (object `clone()` works). The runner names it:
  "array.clone() does not work in the browser runner yet. Use Arrays.copyOf(a, a.length)."
- Exception messages are TeaVM's: `ArrayIndexOutOfBoundsException` has no "Index 5 out of bounds
  for length 3", `ArithmeticException` has no "/ by zero".
- `System.exit(n)` with n other than 0 reports exit code 1, not n.
- Our `Scanner` splits on whitespace only: no `useDelimiter`, no `Scanner(File)`.
- No threads, files, reflection, or network, and only what TeaVM's class library has. A missing
  method is a javac "cannot find symbol" error, so students see it at compile time.
- Browser: needs WebAssembly GC and exception references (exnref): Chrome and Edge 137+, Firefox
  137+ per MDN data. Safari support for exnref is unconfirmed. Older browsers get "this browser is
  too old for the Java compiler" and can still use Python.
- Trust: like the Python judge today, the result is computed on the student's machine. A
  determined student can fake a pass. Fine for practice; not for prizes.

### B. A JDK on Cloudflare Containers (written up, not built)

From the Cloudflare docs (read 2026-11-19: /containers/pricing/, /containers/platform-details/limits/,
/containers/local-dev/):

- **Plan:** Workers Paid, $5 a month. Not available on Free.
- **Included each month:** 25 GiB-hours memory, 375 vCPU-minutes, 200 GB-hours disk. Overage
  $0.0000025 per GiB-second, $0.000020 per vCPU-second, $0.00000007 per GB-second. Billed per
  10 ms while a container runs; CPU only for active use. Each container also has a Durable Object.
- **Instance types:** lite (1/16 vCPU, 256 MiB), basic (1/4 vCPU, 1 GiB), standard-1 (1/2 vCPU,
  4 GiB) and up. A JDK wants basic or standard-1.
- **Cost for the club** (30 students, about 5,000 runs a month, my estimate): with a container that
  sleeps 2 minutes after its last run, meetings and evening practice keep it awake perhaps 40 hours
  a month. basic: 40 GiB-hours memory (15 over, about $0.14), CPU about 1 vCPU-second per run so
  about 85 vCPU-minutes (included), disk 160 GB-hours (included). **About $5.15 a month.**
- **Cold start:** Cloudflare says 2 to 3 s typical, depending on image size. An independent July
  2026 benchmark (alchemy.run, 700 boots) found a 2 s median with a tail out to 20 to 50 s. Add
  JVM start and javac (about 1 to 2 s on a quarter vCPU). Warm runs: about 1 to 2 s, similar to A.
- **Isolation:** each container is its own VM. Inside it the runner must still drop privileges,
  cap time and memory per run (`timeout`, `ulimit`, `-Xmx`), and disable internet for the container.
- **Local development and deploy need Docker.** Wrangler builds the image with Docker on
  `wrangler deploy`, and `wrangler dev` runs containers in Docker. Docker is not installed on this
  machine; the GitHub Actions deploy runner would need it too.
- **Gains over A:** real OpenJDK, exact Java semantics and messages, every library class, and the
  verdict is computed on our server, so points can trust it.

## Decisions for the lead

1. **Ship A for practice now?** Recommended. First test `/lab/editor?editor=1` on a school laptop on
   school wifi: does `/teavm/compiler.wasm` load, and how long does the first Java run take?
2. **B for trusted judging, later.** It needs the Workers Paid plan ($5 a month), Docker for
   whoever deploys, and a decision on whether contest points must come from a server verdict.
   Python has the same trust gap today.
3. **Safari users** (iPads, Macs) may not run Java until Safari ships exnref. If the club has many,
   either build TeaVM with legacy exceptions (not tested) or route them to B.

## Rebuilding public/teavm

```
git clone https://github.com/konsoletyper/teavm-javac && cd teavm-javac
git checkout 0340fab28da146d283ba94df8a36d66a4c635084
# gradle/libs.versions.toml: teavm = "0.17.0-dev-7"
./gradlew :compiler:createDist          # needs Java 25
unzip compiler/build/distributions/dist.zip   # compiler.wasm, *.bin, compiler.wasm-runtime.js
unzip -p ~/.gradle/caches/modules-2/files-2.1/org.teavm/teavm-wasm-gc-deobfuscator/0.17.0-dev-7/*/teavm-wasm-gc-deobfuscator-0.17.0-dev-7.jar \
  org/teavm/backend/wasm/deobfuscator.wasm > deobfuscator.wasm
```

Copy those five files into `public/teavm/` and run `npm test` (`test/java-engine.test.js` compiles
and runs real programs against them).
